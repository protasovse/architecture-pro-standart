### Функциональные требования (Use Cases)  
  
| № | Действующие лица или системы                                                                         | Use Case                                                   | Описание                                                                                                                                                                                                                                                                                                         |
|:-:|------------------------------------------------------------------------------------------------------|------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | Сотрудник внутреннего кол-центра, Система кол-центра (CCS), Сервис ставок (`DepositRateService`)     | Просмотр актуальных ставок по депозитам во внутреннем КЦ   | Сотрудник кол-центра открывает карточку продукта/скрипт звонка, система кол-центра запрашивает у DepositRateService актуальные депозитные ставки (по выбранному продукту, сроку, сумме и т.п.) и отображает их оператору.                                                                                        | 
| 2 | Сотрудник партнёрского кол-центра, Система партнёрского КЦ (PCCS), Процесс выгрузки ставок           | Просмотр актуальных ставок по депозитам в партнёрском КЦ   | Банк периодически формирует файл с актуальными депозитными ставками в согласованном формате (например, CSV/XLSX) и передаёт партнёру по существующему каналу обмена файлами. Система партнёра загружает файл, оператор видит актуальные ставки. Файл сжимается в виде архива с паролем, и отправляется по почте. |
| 3 | Бэк-офис депозитов, Бэк-офис кредитов, Модуль ставок в АБС (`ABSDepositRates`), `DepositRateService` | Обновление ставок в АБС и их распространение во все каналы | Сотрудники бэк-офиса депозитов/кредитов обновляют ставки в модуле ставок АБС. `DepositRateService` по расписанию синхронизирует изменения в свой кеш. При следующем обращении внутренних каналов (IB, сайт, CCS) используются новые значения. Регулярно формируется новый файл ставок для партнёрского КЦ.       |
| 4 | Сотрудники поддержки/операций, `DepositRateService`, CCS, PCCS                                       | Диагностика и контроль корректности ставок                 | При расхождениях ставок оператор поддержки может сверить значения ставок, использованных в CCS/PCCS, с данными в `DepositRateService` и АБС, проверить дату последней синхронизации и последней выгрузки файла, инициировать внеплановую выгрузку.                                                               |

### Нефункциональные требования  
  
| № | Требование                                                                                                                                                                                                                                                                                                              | 
|:-:|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | Внутренний кол-центр, партнёрский кол-центр, сайт и интернет-банк должны использовать согласованные депозитные ставки из одного источника (`DepositRateService`). Максимально допустимое отставание кеша `DepositRateService` от АБС — не более 15 минут, файла партнёру — не более одного рабочего дня (в рамках MVP). |
| 2 | Система кол-центра не должна обращаться к АБС напрямую для чтения ставок. Все обращения идут только к `DepositRateService`, чтобы не увеличивать нагрузку на БД АБС и не ломать её ограничение на вертикальное масштабирование.                                                                                         |
| 3 | Внутренний кол-центр должен оставаться работоспособным (консультация по ставкам) при временной недоступности АБС — за счёт кеша ставок в `DepositRateService`. Для партнёрского КЦ достаточно иметь последнюю успешно загруженную версию файла.                                                                         |
| 4 | Канал взаимодействия CCS ↔ `DepositRateService` должен быть защищён (TLS, внутренняя сеть). Файл ставок для партнёра не должен содержать персональных данных клиентов и должен передаваться по согласованному защищённому каналу (например, через уже существующую B2B–зону обмена файлами).                            |     
| 5 | Формат файла ставок для партнёра должен быть максимально близок к текущим XLS-файлам, чтобы минимизировать изменения в процессах и формулах бэк-офиса, но при этом иметь однозначно описанную структуру (словари значений, версии формата).                                                                             |     
| 6 | Необходимо логировать: моменты синхронизации ставок из АБС в `DepositRateService`, успешные/ошибочные выгрузки файла, обращения CCS к API ставок. Логи должны позволять восстановить, какими ставками пользовался оператор в конкретный момент времени.                                                                 |     
| 7 | Решение должно максимально использовать текущую архитектуру MVP депозитов: модуль ставок в АБС как источник истины, `DepositRateService` как единый сервис ставок для цифровых каналов. Новые изменения не должны требовать переработки IB/сайта.                                                                       |     
| 8 | Время ответа `DepositRateService` на запрос ставок от CCS — субсекундное для 95-го перцентиля при типичной нагрузке (операторы работают в режиме разговора с клиентом).                                                                                                                                                 |     
  
---  
  
### Решение  
  
#### Общая идея  
  
1. **Единый источник ставок** остаётся в АБС (модуль депозитных ставок).    
2. **`DepositRateService`** — единый сервис ставок для всех каналов (IB, сайт, внутренний КЦ, далее — другие).    
3. Для **внутреннего кол-центра** добавляется использование API `DepositRateService`.    
4. Для **партнёрского кол-центра** организуется **регулярная выгрузка файла ставок** из DepRateSvc в`DepositRateService` согласованном формате (CSV/XLSX) в зону обмена файлами, откуда партнёр забирает файл и загружает в свою систему.    
5. Текущий процесс ведения ставок бэк-офисом (в АБС) не меняется — меняется только слой распространения ставок.
