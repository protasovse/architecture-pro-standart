## **ADR — Онлайн-заявка на кредит**

### Онлайн-заявка на кредит в интернет-банке и на сайте

### **Автор:** Протасов Сергей (архитектор цифровой трансформации)

### **Дата:** 2025-12-02

---
## **Функциональные требования**

| № | Действующие лица / системы            | Use Case                               | Описание                                                                                              |
|:-:|---------------------------------------|----------------------------------------|-------------------------------------------------------------------------------------------------------|
| 1 | Клиент (IB)                           | Подача заявки из интернет-банка        | Клиент выбирает кредит, сумму, срок, подтверждает заявку СМС-кодом. Заявка уходит в CreditAppService. |
| 2 | Клиент (Сайт)                         | Подача заявки новым клиентом           | Клиент вводит ФИО, телефон, паспортные данные (опционально). Заявка уходит в CreditAppService.        |
| 3 | CreditAppService → Скоринг            | Онлайн-скоринг по заявке               | Сервис отправляет данные в скоринг, получает результат. Для новых клиентов — c запросами в БКИ.       |
| 4 | CreditAppService → Кредитный конвейер | Передача заявки в конвейер             | Заявка передаётся в Camunda-конвейер для ручной/полуавтоматической обработки.                         |
| 5 | Кредитный конвейер                    | Обработка заявки                       | Сотрудник кредитного отдела анализирует заявку, использует данные скоринга и внутренние данные.       |
| 6 | Конвейер → CreditAppService           | Передача статусов                      | Конвейер отправляет статусы: принято, в обработке, одобрено, отказано, требуется визит в отделение.   |
| 7 | CreditAppService → IB                 | Отображение статусов                   | Клиент видит актуальный статус заявки в интерфейсе интернет-банка.                                    |
| 8 | CreditAppService → SMS-ядро           | Информирование клиента                 | Клиент получает СМС после подачи заявки, решения и при необходимости визита в офис.                   |
| 9 | IB → Клиент                           | Отображение предодобренных предложений | IB получает данные о предодобренных предложениях и выводит упрощённую форму заявки.                   |

## **Нефункциональные требования**

| № | Требование                                                                                  |
|:-:|---------------------------------------------------------------------------------------------|
| 1 | IB не должен напрямую обращаться к АБС (ограничение ИБ и нагрузки).                         |
| 2 | Сервис кредитных заявок должен работать 24/7 и поддерживать горизонтальное масштабирование. |
| 3 | Время ответа скоринга ≤ 2–3 секунды.                                                        |
| 4 | Все интеграции — только через защищённые каналы (TLS).                                      |
| 5 | Нельзя нагружать скоринг лишними фоновыми проверками.                                       |
| 6 | Обмен АБС ↔ Конвейер возможен только раз в сутки (ограничение текущей архитектуры).         |
| 7 | Система должна выдерживать пиковую нагрузку (маркетинговые кампании).                       |
| 8 | Все операции должны логироваться для аудита.                                                |
| 9 | Система должна корректно работать при сбоях скоринга или БКИ (ретраи, очереди).             |

## **Альтернативы**

### **Альтернатива 1 — IB вызывает скоринг напрямую**
* плюсы: проще
* минусы: нарушает ИБ, сложно управлять нагрузкой, нет единого места логики

### **Альтернатива 2 — Сайт и IB пишут заявки напрямую в АБС**
* АБС перегружена
* нельзя обеспечивать онлайн-скоринг
* нет масштабирования
* нарушает ограничения ИБ

### **Альтернатива 3 — Сайт → Конвейер напрямую**
* сайт не обладает нужным уровнем доверия
* конвейер не должен быть публичным входом
* не решает задачи уведомлений и агрегирования статусов

### **Альтернатива 4 — Кафка и микросервисы**
* для всех систем сделать адаптер

---

## **Недостатки, ограничения, риски**

* Скоринг нельзя перегружать — нужна защита от массовых запросов.
* АБС остаётся узким местом при создании договора.
* Обновление данных между АБС ↔ Конвейер по-прежнему раз в сутки (ограничение платформы).
* Ошибки БКИ могут блокировать заявку — нужно резервное поведение.
* При большом маркетинговом всплеске требуется масштабирование скоринга и CreditAppService.
* IB работает на старой платформе, плохо масштабируется.
